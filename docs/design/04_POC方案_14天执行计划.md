## 0. 先处理你 2024-07 那条原始笔记

> 拍照药品剂量，使用方法，自动归类成笔记和闹钟，定时提醒吃药，chatbot问答，比如上个月血糖是多少
> **老年人的 extended eyes and memory**

最后那句是整条笔记里最好的东西。**"extended eyes and memory" 就是产品定位，别改。** 下面的方案全部是在把这句话落地，只做了一处关键手术。

| 你写的 | 判断 | 理由 |
|---|---|---|
| 拍照药品剂量、使用方法 | **保留，作为唯一入口** | 这就是 "extended eyes"。84% 的老人看不清说明书，58% 看不懂术语——这是大模型相对于任何硬件的唯一不可替代之处 |
| 自动归类成笔记和闹钟 | **保留，但把"自动"改掉** | 改成「AI 解析 → 子女逐条确认 → 才生效」。中文药盒商品名/通用名/规格排版混乱，VLM 读错一次就是安全事故。这条是红线，不是可优化项 |
| 定时提醒吃药 | **保留，但换交付通道** | 你可能默认是小程序或 App。小程序这条路个人主体走不通（见下一节），必须走安卓 APK 侧载 |
| chatbot 问答 | **保留，但砍到只答 3 类问题** | 开放域问答在两周内做不到可信，且越界就是医疗建议 |
| **"比如上个月血糖是多少"** | **砍掉** | 见下 ↓ |

### 唯一的一处手术：把 "memory" 的定义改掉

"上个月血糖是多少"这个例子，暴露了一个假设：**记忆是老人自己录进去的。**

但血糖要进系统，只有两条路——老人每天手动输入（他们不会，60 岁以上网民只有约 30% 能独立完成"出示健康码"这个动作），或者接血糖仪（两周内做不完，且是硬件问题）。**这个 memory 永远填不满，功能就永远是空的。**

正确的做法是：

> **只做系统自己就能产生的记忆，不做需要老人输入的记忆。**

"我今天吃药了没？" —— 这个问题系统能免费回答，因为按钮的点击数据它本来就有。它和"上个月血糖是多少"在老人听来是同一类问题、同样有价值，但**获取成本是零**。

血糖、血压不是不做，是**等到吃药这条闭环跑通、老人已经每天在按那个按钮之后再做**。那时候加一句"顺便量一下血压，念给我听"才有可能成立——因为习惯已经在了。

**一句话：extended eyes 立刻做，extended memory 只做零输入的那一半。**

> **补充（2026-08）**：「定期检查报告太长、看不懂也记不住」这个观察，正好补上了 extended memory 缺的那一半——**化验单是由子女在复查后拍一次，不需要老人做任何输入**，完全通过上面那条规则。而且它和药盒是同一个事件的两半。展开见第 11 节。

## 1. 先说三个会杀死大部分方案的约束

在讨论「做什么」之前，先讲「不能做什么」。这三条决定了形态，不是细节。

### 约束一：个人主体做不了微信小程序里的健康提醒

- 个人主体小程序**完全禁止医疗/药品类目**。健康管理类工具（BMI 计算器一类）可以过，但不能涉及任何诊疗建议。
- 更致命的是：**长期订阅消息只对政务民生、医疗、交通、金融、教育等二级行业开放**，个人主体拿不到。你只能用一次性订阅消息——用户授权一次，你才能发一条。
- 这意味着：**「小程序每天定时推送吃药提醒」这条路，个人开发者是走不通的。** 不是难，是接口层面拿不到。

### 约束二：个人订阅号也堵死了

2014 年 8 月 26 日之后注册的个人订阅号**无法申请微信认证**。没有认证就没有语音识别接口、没有客服消息、没有模板消息。公众号这条路同样不通。

### 约束三：老人的手机上装不下第 8 个 App

调查显示中老年人手机上常用应用固定在 3–7 个；60 岁以上网民中只有约 30% 能独立完成「出示健康码」这个动作。**任何需要老人自己下载、注册、登录、找入口的方案，转化率接近零。**

### 由此得出的唯一干净路径

> **安卓 APK，由子女在探亲时/通过微信文件传输侧载到父母手机上。**

理由：老人手机安卓:iOS ≈ **9:1**；45 岁以上安卓用户中华为占 48.9%，vivo 16.3%，荣耀 13%，小米 10.6%——全是支持侧载的国产安卓。侧载绕开了主体资质、类目审核、推送配额的全部问题。本地 `AlarmManager` + TTS 就能做定时语音播报，不需要任何推送服务。

这条路走不到千万级（上架国内应用商店需要软著 + 备案 + 多数需企业主体），但**它是 14 天内让 5 个真实 70 岁老人用上的唯一现实路径**，而 POC 阶段你要的就是这个。规模化问题留到 POC 验证之后再解。

## 2. 把「老人健康助手」拆开：五个候选痛点打分

| 候选痛点 | 发生频率 | 后果严重度 | 现有方案缺口 | 2 周可做性 | 总评 |
|---|---|---|---|---|---|
| **A. 吃药：记不住 + 看不懂 + 说不清** | 每天 2–4 次 | 高（急诊/住院） | **大** | 高 | **★★★★★** |
| B. 跌倒检测/紧急呼救 | 罕见但致命 | 极高 | 中（手表已覆盖） | 低（需硬件+误报调优） | ★★☆ |
| C. 挂号/就医导航 | 每月 1–2 次 | 中 | 中（微医等已做） | 低（需医院数据接口） | ★★ |
| D. 孤独陪伴/聊天 | 每天 | 中 | 中 | 高 | ★★★（但难验证价值） |
| E. 防诈骗 | 每周 | 高（财产） | 大 | 中 | ★★★★（值得记下来） |

**A 胜出，而且不接近。** 它是唯一一个「每天发生 × 后果严重 × 现有方案真的没解决 × 两周能做出来」四项全中的。

### 支撑数据

**频率与规模**
- 中国 60 岁以上人口 2.67 亿（2021 年底），十四五期间将破 3 亿
- 空巢老人占老年人口**超过一半**，部分大城市和农村超 70%，规模约 1.3–1.5 亿；高龄独居空巢老人 772 万
- 「独居」在多项研究中被反复确认为服药依从性差的独立风险因素

**依从性有多差**
- 山东农村老年慢性病患者中，**45.2% 用药依从性差**
- 不依从的最主要表现是「忘记服药」，占 **77.1%**
- 北京 80 岁以上老人多重用药比例 **64.8%**，安徽 **82.4%**；2022 年一项多中心研究中住院患者用药超过 10 种的比例达 **50.4%**

**后果有多严重**
- 门诊老年患者潜在不适当用药（PIM）发生率 **31.72%**
- 心血管内科老年多重用药患者中，按 Beers 标准 PIM **50.5%**，按《中国老年人潜在不适当用药判断标准》**66.5%**

**为什么现有方案不管用**
- **84% 的老人因字号太小看不清药品说明书，58% 因专业术语看不懂关键信息**
- 药监局刚刚才发布《药品说明书适老化改革试点工作方案》征求意见稿——**意味着这个问题至今没解决**
- 智能药盒（HiPee 等）解决「忘记」，但完全不解决「看不懂」和「这两个药能一起吃吗」

### 最尖锐的那一刻

不是「早上八点该吃药了」，而是——

> **老人从医院回到家，桌上摊着 6 个药盒和一张字迹潦草的医嘱单，子女不在身边。他要在接下来的 90 天里，每天执行一套自己从来没有真正听懂的方案。**

错误就是在这一刻被锁定的。此后每天重复。智能药盒解决不了，因为药盒不知道盒子里装的是什么、为什么装、能不能一起吃。

**这正是大模型相对于「一个 30 块的分药盒 + 闹钟」的唯一不可替代之处。** 如果你的产品只做提醒，你就是在和一个 30 块的塑料盒子竞争，而且你会输。

## 3. 收窄后的产品：「吃药了」

**一句话**：子女拍一次药盒，老人此后每天只需要听和按一个大按钮。

**给谁**：日活是老人（70+，独居或空巢，3 种以上长期用药）。**装机人和把关人是子女**——这是关键的双角色设计，不是妥协。

### 三个交付物

**① 大字用药表（一张图片，不是一张纸）**

> ⚠️ **此处已相对初稿修订。** 初稿是"打印出来贴冰箱"，那不成立——见 §14-⑯。

子女拍完药盒后，系统生成一张超大字用药表 —— 时间、药名、几片、什么样子（带真实药盒照片）。
**三个去处，按优先级：**

1. **设成老人手机锁屏**（APK 内一键）—— 主路径
2. **发到家庭微信群 / 存为图片** —— 通用兜底，老人自己能打开放大看

**不做 PDF 打印导出。**

> **为什么锁屏比冰箱好**：老人一天看几十次锁屏，**零导航、永远在手边**，而冰箱只在厨房。
> 而且壁纸即使 App 被卸载也还在，兜底更硬。
>
> **技术很便宜**：`WallpaperManager.setBitmap(bmp, null, true, FLAG_LOCK)`，
> `SET_WALLPAPER` 是普通权限，约半天。
>
> ⚠️ **但必须可选且说清代价**：老人的锁屏往往是孙子的照片，**换掉它有情感成本**。
> 让子女明确知道自己在换什么，不要偷偷替换。

**② 老人手机上的 APK（闹钟式，不是"只有一屏"）**

> ⚠️ **此处已相对初稿修订。** 初稿写的是"只有一个按钮"，那是错的——见 §14-①。

**平时它完全不在屏幕上。** 手机是老人的，他要用微信、接电话。App 只在三个时刻出现：
到点时（全屏，唯一允许接管的时刻）、有待办时（通知栏，不占屏）、老人主动打开时。

到点了 → 全屏亮起 + 大声播报：「王阿姨，现在早上八点，该吃降压药了，白色小盒子那个，一片。」

屏幕上：**一张巨大的药盒真实照片** + 三个按钮，按闹钟的心智模型：

| 按钮 | 尺寸 | 行为 |
|---|---|---|
| **吃了** | 绿色，占屏 ~28%，40sp | 写入 `confirmation_event` → 熄屏。反馈只有「知道了」，**不表扬** |
| **等会儿吃** | 灰底，主按钮 55% 高 | 固定推迟 30 分钟，无时间选择器。**连按 3 次改为通知子女** |
| **这次不吃** | 浅黄底，同上 | 进入追问屏：我不在家 / 药吃完了 / 今天不舒服 / 医生说停了。**可跳过** |

次级：**长按说话**（模仿微信语音，这个人群唯一学会的手势）。

> **为什么必须给"等会儿吃"和"这次不吃"**：老人在公交车上、药在家里时，
> 若唯一的出口是「吃了」，**设计本身就在逼他撒谎**。
> 给一个诚实的出口，比任何置信度算法都有效。

**③ 子女端（手机网页，微信里点开，不装 App）**
- 拍照建档 → 逐条确认 → 设置称呼与联系方式 → 生成
- 到点后 30 分钟没确认 → 子女收到提醒
- 老人问了越界问题（改剂量、说不舒服、想停药）→ **原话 + 原始录音转给子女**
- 子女可回复 → **回传给老人，播放原声**（闭环，没有它这个功能三周内会死）
- 看板用**三态**：已确认 / **已点击（存疑）** / 未确认

技术上用 PushPlus / WeCom酱推到子女微信，个人开发者可用，免费额度够 POC。
拍照用 `<input capture>` 调系统相机（微信 WebView 里 `getUserMedia` 不可靠、
`wx.chooseImage` 需认证服务号拿不到）。

## 4. 这里的 Agent 到底 agent 在哪

不是套壳聊天机器人。是一条真正的多步流水线，每步都可能失败并需要回退：

```
子女拍照（药盒 + 医嘱单，5–9 张）
        ↓
[1] 视觉解析      Qwen-VL-OCR：药名/规格/用法用量/生产厂家
        ↓
[2] 实体归一      "苯磺酸氨氯地平片" / "络活喜" / "氨氯地平" → 同一实体
                  ← 这一步是护城河，也是最容易翻车的一步
        ↓
[3] 安全检查      · 重复用药（两个盒子同一通用名 —— 最常见也最危险的错误）
                  · 《中国老年人潜在不适当用药判断标准(2017版)》命中
                  · 明显的相互作用对
                  → 命中即停，不生成方案，直接推给子女人工确认
        ↓
[4] 排程合成      "一日三次" + "饭前" + 老人作息 → 具体时刻表
                  歧义处（如"必要时服用"）→ 不猜，标黄，问子女
        ↓
[5] 日常执行      定时播报 → 等待确认 → 未确认则升级
        ↓
[6] 问答          ASR（Qwen3-ASR，明确支持 22 种中文方言 + 老人语音）
                  → 检索该老人自己的用药档案 → 大白话作答 → TTS
                  → 任何触及"改不改药"的问题，一律不答，转子女
```

**第 3 步和第 6 步的"拒答"是产品的核心，不是限制。** 一个会说「这个我不能替医生决定，我已经告诉你儿子了」的助手，才是可以给老人用的助手。这既是伦理底线，也是你唯一的合规护身符。

## 5. 两周里砍掉什么（这一节比上面都重要）

### 做

- 一个老人（安卓 APK）+ 一个子女（手机网页 + 微信收通知）
- **拍照采集**：系统相机 → 上传 → 服务端 VLM 检查 → 缺什么说什么（不写使用说明）
- 拍照解析 → 人工校对页（**子女必须逐条确认才生效**，剂量字段默认不勾选）
- 定时 TTS 播报 + **三按钮**（吃了 / 等会儿吃 / 这次不吃）+ 待办态 + 未确认升级
- **「这次不吃」四选项追问**（信息密度最高的一次点击）
- 语音问答，**只答三类**：这药干什么的 / 我今天吃了没 / 这两个能一起吃吗
- **升级闭环**：分诊 → 持久化 outbox → 推子女 → **子女回复回传播放**
- 重复用药检测 + PIM 清单命中（手工录入 60–80 条，一天工作量）
- **大字用药表图片**（→ 一键设锁屏 / 发家庭群）
- **医生版**：老人端「给医生看」全屏 + 可转发图片
- **子女看板三态**（已确认 / 已点击存疑 / 未确认）
- **图标与配色**：`#FFD500` 底黑字，主按钮 `#0B6B33`

### 不做

- ❌ 账号体系、注册登录（子女端用 URL 里的随机 token）
- ❌ 微信小程序 / 公众号（见约束一、二）
- ❌ 应用商店上架、任何资质流程
- ❌ **第二联系人升级**（优先级、谁先响应、去重 —— 真正的复杂度，5 个用户不需要）
- ❌ **多子女 / 老伴 / 护工多联系人**，POC 只支持 1 个
- ❌ **网页内实时取景**（`getUserMedia` 在微信里不可靠，改拍后反馈）
- ❌ **条形码 / 追溯码解析**（不解决"怎么吃"，且是外部付费依赖 —— v2 作为校验器）
- ❌ 完整药品数据库对接（VLM 直接读盒子 + 几百条常用老年药 JSON）
- ❌ 完整相互作用引擎（只做重复用药 + 手工 PIM 清单）
- ❌ 支付、订阅、多语言、**iOS**（老人安卓:iOS ≈ 9:1，遇到 iPhone 用户先换人或 Wizard-of-Oz）
- ❌ 血压血糖记录、运动、饮食、聊天陪伴 —— **一个都不加**
- ❌ 依从率数字、趋势图表、任何形式的**计分/打卡/连续天数**
- ❌ **任何打印导出（PDF / A4 排版）**

> **这个产品从头到尾不需要一张纸。** 不需要打印机、扫描仪或任何外设。
> 全部载体只有两样：**老人的安卓手机、子女的微信。**
> 这不只是省事——**每多一个硬件依赖，就多一批装不上的家庭。**

> **老人端永远不显示评分。** 不做 streak、不做红绿灯、不做"本月漏了 3 次"。
> **任何计分都会制造说谎的动机**，直接污染你唯一的数据源。

> 判断标准：**任何不能被「老人今天有没有正确吃药」这一个指标解释的功能，两周内一律不做。**
>
> 唯一通过这条测试的追加项是**化验单捕捉**——因为复查是用药方案改变的触发点，不捕捉它，时刻表会悄悄过期变错。见第 11 节。

## 9. 什么情况下我是错的

诚实地列出来，第 11 天用它来检验：

1. **老人根本不看手机。** 如果他们把手机放在客厅充电、人在卧室，语音播报就白做了。→ 观察一下他们手机平时放哪。如果败在这里，正确的下一步是**智能音箱**（小爱/小度已在老人家里）而不是手机。
2. **子女不愿意花 5 分钟拍照。** 如果冷启动这一步都过不去，整个方案不成立。→ 所以必须给这 5 分钟一个**立刻可见的回报**。初稿指望「打印贴冰箱」，但多数家庭没有打印机；现在改由**试听**承担（听到「王阿姨，现在早上八点…」那一刻的情绪冲击）+ **大字表图片发家庭群**。第 11 天要给这一步计时。
3. **按钮被随手按掉。** 老人会为了让声音停下来而按「吃了」，而不是真的吃了。→ 「等会儿吃 / 这次不吃」两个诚实出口已经缓解了其中最大的一类（人在外面），但**没有消除**。应对分三层：**(a) 消除作弊动机**——绝不向老人展示评分、按下后不表扬、子女侧措辞去评判化；**(b) 用免费旁证打置信度**——响应延迟（0.8 秒秒按高度可疑）、屏幕停留、延迟方差，报三态不报二态；**(c) 若要硬验证**，最优解是**周药盒每周拍一张**（数空格，验证的是"药离开了盒子"，7 天一次操作成本极低）。第 11 天重点看这个。
4. **VLM 读错药名。** 中文药盒商品名+通用名+规格排版混乱，错一次就是安全事故。→ 所以子女**必须**逐条确认，永远不做全自动。这一条不是可优化项，是红线。
5. **老人一次都不问问题。** 那么语音问答就是伪需求，产品退化成一个带照片的闹钟——而那个东西不值得做。
6. **抽屉里没有旧化验单。** 我假设慢病老人家里存着一沓过去的报告（第 11 节的关键一步）。如果实际上他们看完就扔、或者报告只在医院系统里，那纵向数据要真等 3–6 个月才有——归档这条线的验证周期会长得多。**第 11 天上门时先问这一句，成本为零。**

## 10. 五条不能越的线

**① 安全**：任何时候都不给诊疗建议、不建议改剂量、不建议停药。只做**转录 / 对比 / 放大**三件机械的事。老人说「我头晕」→ 唯一正确的回应是把这句话原封不动推给子女。写在系统提示词里不够，要写成**代码里的硬规则 + 一组必须通过的拒答测试**。

> **这条不只是伦理，是商业生死线。** 医疗器械软件的界定核心是"是否用于医疗用途（诊断/预防/监护/治疗）"。守住这条线 → 属健康管理软件，可正常上架；越过 → **注册周期以年计、成本百万级、整个产品形态要重做**。

**② 人在环内**：AI 解析 → **子女逐条确认 → 才生效**，永不全自动。剂量字段默认不勾选。VLM 把 5mg 读成 50mg 时输出的 JSON 依然工整自信，**从结果上完全看不出来**。

**③ 承诺必须真实**：投递确认前只能说「我这就去问」，不能说「已经告诉你女儿了」。需要**持久化 outbox + 状态机**，重试耗尽后诚实降级 +满屏拨号按钮。**对一个正在等待的 78 岁老人撒谎，是这个产品最不可接受的失败。**

**④ 隐私**：**记录事件，不记录内容**。不做常开麦克风、不做摄像头。安全类事件不可屏蔽且老人知情，生活类老人有权说"这条别告诉我女儿"——**一个完全没有隐私的老人会拒绝使用这个产品**。

**⑤ 信任**：老人是脆弱用户群，也是诈骗高发目标。永远不索要支付信息、不弹广告、不引导购药、不申请无关权限。一旦子女怀疑这是个卖药的，产品就死了。

> **附加铁律：这份数据绝不能当作考核护工的 KPI。** 一旦确认率变成考核数字，就会有人替老人按按钮——**你亲手制造了污染源**。

## 11. 定期检查报告：同一个入口，但要克制

### 为什么这不是新功能，而是核心功能缺的那一块

先纠正一个可能的误解：化验单和药盒**不是两个功能，是同一个事件的两半**。

```
老人去复查
    ↓
拿到化验单（30–40 项指标）
    ↓
医生看完，调药 ← 关键：药方变了
    ↓
拿新药回家 —— 新旧药盒并存
```

**慢病老人的用药方案改变，几乎全部由复查触发。** 这意味着：如果系统不知道复查发生了，它手里那张时刻表就会在某一天悄悄变成错的——而这是比"忘记吃药"危险得多的失败模式。老人按旧方案继续吃，或者新旧两盒同名药一起吃（重复用药，最常见也最危险的老年用药错误）。

所以化验单捕捉在 POC 里的**最小职责不是归档，而是触发**：一次复查 = 一次「你爸妈的用药方案可能变了，请重新拍一下药盒」。归档和查询是顺带几乎白拿的。

这也回答了第 5 节那条"任何不能被『老人今天有没有正确吃药』解释的功能一律不做"——**复查捕捉恰恰是在保证那个指标不失效**。它没有破例。

### 但「供以后查询」这个价值，两周内验证不了

这一点必须说清楚，否则你会在第 14 天感到挫败：

> **归档类功能的价值，在定义上无法在两周内被验证。** 一个人手里得有 2 份以上的报告，"查询历史"才有意义——而慢病复查间隔是 3 个月。你第 14 天最多只有每人 1 份。

正确的做法是：**捕捉现在就建（不可逆，不建就永远没数据），查询层延后。** 但可以在第 11 天上门时做一件事——**问子女要过去的旧化验单**。老人家里的抽屉、床头柜、饼干盒里通常存着一沓。一次性拍完，你立刻就有了纵向数据，直接跳过 3 个月的等待。

> 这是整个方案里最被低估的一步。去问那个抽屉。

### 分层：老人 / 子女 / 医生，三种输出

一份化验单要生成三样东西，因为三个人要的完全不同：

| 给谁 | 形态 | 内容 |
|---|---|---|
| **老人** | APK 上一屏，超大字，语音念一遍 | **3 句话**。「这次一共查了 32 项，有 3 项超出范围。跟上次比，血糖降下来了。医生让你继续吃原来的药。」不解释任何医学含义 |
| **子女** | 微信里一条 + 网页详情 | 全部异常项、与上次对比的升降箭头、**「下次复诊建议问医生这 3 个问题」** |
| **医生** | 一页 A4：**转发微信群 / 存图 / 打印**，<br>外加**老人端「给医生看」全屏** | 近 3 次关键指标横向对比表 + 当前用药清单 |

**第三项是最被忽视、也可能最有杀伤力的。** 老人复诊时医生问"上次的化验单呢"，老人翻不出来；门诊 3 分钟，说不清楚。有了三次对比表，医生会明显更好沟通，老人会觉得有面子，子女会因此觉得这个东西有用。**这是一个会让人主动去用的理由，而不是一个需要被提醒去用的功能。**

**两种带法，都不依赖打印机：**

1. **老人端「给医生看」全屏**（首页一个按钮）—— 点一下全屏显示，直接把手机递给医生。
   **零准备、永远可用、不依赖任何人提前做事** ← 主路径
2. **转发到家庭微信群 / 存成图片** —— 子女侧一键，老人复诊时也能自己在微信里打开

> **PDF 打印导出：不做。** 和「冰箱大字表」同一个理由——依赖多数家庭没有的硬件，
> 而排版、分页、字体这些工作量并不小。**砍掉它省下的时间够做完「给医生看」那一屏。**
>
> 这意味着**这个产品从头到尾不需要任何纸**，也不需要打印机、扫描仪或任何外设。
> 全部载体只有两样：**老人的安卓手机、子女的微信。**

> ⚠️ **一个未经验证的假设**：门诊医生会不会愿意接过一部手机看。
> 时间压力下他们可能更想要纸。但一屏清晰的三次对比只花 5 秒，值得一试——
> **这条第 11 天验证不了（你不在诊室），要单独找机会问一位基层医生**，
> 正好和 B 端要接触社区卫生服务中心那条线并到一起。

### 安全红线：只做三件机械的事

化验单解读离"诊断"只有一步之遥。所以把边界画死：

> **对检查报告，产品只做三件不涉及医疗判断的事：转录、对比、放大。**

- ✅ **转录**：「血肌酐 118 μmol/L，参考范围 57–97，↑」——这行字本来就印在单子上，你只是让它看得见
- ✅ **对比**：「上次 96，这次 118」——这是减法
- ✅ **放大**：字号、语音
- ❌ **绝不做**：「这说明你的肾功能在下降」「这个指标偏高要注意饮食」「可能是……引起的」

一旦越过第四条，你在行医。而且个人主体没有任何资质做这件事。

**影像报告（CT / B超 / 心电图）另有一条规则：只原文抽取「诊断意见 / 结论」那一段，一个字都不改、不概括、不解释。** 放射科结论里的措辞（"考虑"/"不除外"/"建议随访"）每个词都有精确含义，概括一定失真。抽出来、放大、存档，仅此。

### 技术：比你以为的简单，但有一个坑

**捕捉**
子女拍 1–3 张 A4 热敏纸/打印件 → `qwen-vl-ocr`。化验单其实是**结构化的表格**（项目/结果/单位/参考范围/↑↓），VLM 处理得相当好，比读药盒简单。

**结构**
```json
{
  "report_date": "2026-05-12",
  "report_type": "生化全套",
  "hospital": "XX市第一人民医院",
  "image_ref": "blob://...",          // 原图永远保留
  "items": [
    {"raw": "血肌酐", "code": "CREA", "value": 118,
     "unit": "μmol/L", "ref": [57, 97], "flag": "H"}
  ]
}
```

**那个坑：指标名归一化。** 谷丙转氨酶 / ALT / 丙氨酸氨基转移酶 是同一个东西；不同医院单位还可能不同（mg/dL vs mmol/L）。**不做归一化，就没有"对比"，整个价值链断掉。**
→ 手工整理一张 **200 项左右**的常用指标映射表（含单位换算），覆盖老年慢病复查 95% 的项目。一天的工作量，且这是这个 repo 里最有复用价值的资产之一。

**检索：不要上向量库。**
一个人一辈子也就几十份报告、几千个数据点。这是**结构化小数据**，SQL + 一组固定意图（某指标最新值 / 某指标趋势 / 本次所有异常项 / 上次复查是什么时候）就够了，而且比 RAG 准确得多、可解释得多。在几十份化验单上做向量检索是典型的过度设计。

**隐私：这一块比药盒严重得多。**
化验单上有姓名、住院号、有时有身份证号。
- 入库时对原图做**遮蔽处理**（姓名/证件号打码），只保留脱敏版
- 优先本地存储，服务端只存必要的结构化字段
- **GitHub repo 里绝不放任何真实报告**。evals 用你自己的，或手工造的合成样本

### 两周里到底做多少

**做（约 +1 天，全部在子女端网页，APK 一行不改）**
- 化验单拍照 → 解析 → 子女校对 → 存档
- 生成「子女版异常项清单」+「下次问医生这 3 个问题」
- 触发一次「药方可能变了，请重拍药盒」
- 第 11 天上门时，**把抽屉里的旧报告全拍了**

**不做**
- ❌ 趋势图表（数据量还不够，图是空的）
- ❌ 老人端的化验单语音问答（等有 2 份以上再说）
- ⚠️ 医生版：**只做「老人端『给医生看』全屏 + 一张可转发图片」两条**，
  **PDF 打印导出不做**——依赖硬件，且排版分页工作量不小。
  砍掉它省下的时间够做完「给医生看」那一屏
- ❌ 影像报告解析（先只做化验单一种，形态最规整）

### 排期影响

约 **+1 天**，全部在子女端网页（APK 一行不改），已合并进 **§6 的日程表**（第 3、5、5.5、11 天）。
从 12–13 天的缓冲里挪。**做不完先砍化验单，不砍第 11 天。**

## 12. 记下来，但现在不做

**防诈骗助手**（第 2 节候选 E）在打分中排第三，和本项目共享同一套基础设施：同样的老人端 APK、同样的语音入口、同样的「转给子女」升级机制。

功能优先级现在是：**① 吃药闭环 → ② 复查报告归档与查询（等数据攒够）→ ③ 防诈骗**。血压、运动、饮食、聊天陪伴全部排在这三个之后——它们都需要老人主动输入，而那正是这个人群做不到的事。

所有功能共用**老人手机上唯一那个大按钮**，这才是有复利的路径。

## 13. 战略重定位：从「助手」到「事实层」

### 真正的问题：分布式照护里没有一个可信信源

远程子女面对的不是"信息太少"，是"**每一条信息都经过了一个有动机或有损伤的过滤器**"：

| 信源 | 失真原因 |
|---|---|
| 老人自述 | **报喜不报忧**（怕子女担心）、记错（认知衰退）、**刻意隐瞒**（怕被送养老院——摔跤尤其会瞒） |
| 护工/保姆 | 有动机隐瞒失误（漏喂药、老人摔了）；也可能被冤枉 |
| 兄弟姐妹转述 | 各自带着愧疚和立场，常演变成互相指责 |
| 医生 | 门诊 3 分钟，全部依赖老人自述——**失智老人的自述本身不可靠**，而子女不在场就没人能提供准确病史 |

失智让这件事从"难"变成"不可能"：**当唯一的第一现场目击者本人记忆受损时，家庭内部再怎么沟通也生成不出事实。** 必须有一个外部的、无立场的记录。

### 关键设计原则：它必须同时保护护工

这一条决定产品能不能落地。

一个纯粹"监督护工"的产品，护工会消极抵抗——拔电源、说没网、替老人按按钮。但**护工同样是失真的受害者**：中期失智的典型症状之一是**妄想指控**（"保姆偷了我的戒指"、"她一天没给我饭吃"）。目前护工对此毫无自证手段，这是护工行业最大的职业风险之一。

> **同一份客观记录，对子女是监督，对护工是免责。**

把它明确定位成后者，护工会主动配合甚至主动记录。这不是话术，是真实的利益一致。**这个 framing 是整个方向能否成立的关键。**

### 头脑风暴：远程子女 × 老人的痛点清单

**A. 事实缺口（本节主线）**

| # | 痛点 | 现状 | 你已有的基础设施 |
|---|---|---|---|
| A1 | 药到底吃没吃 | 老人说吃了、护工说喂了，都不可验证 | ✅ **按钮点击流已经是一份客观记录** |
| A2 | **摔跤被隐瞒** | 老人怕被送养老院会主动瞒。而一次跌倒是极强的高危信号 | 需要新采集 |
| A3 | 吃饭喝水 | 脱水在老人中极常见、极危险、且完全不可见 | 需要新采集 |
| A4 | **认知状态的渐变** | 子女 3 个月回一次，感受到的是断崖；实际是缓慢滑坡。**没有基线就无法判断"是不是变差了"** | 见下 D1 |
| A5 | 夜间游走 / 日落症候群 | 白天电话里完全听不出来 | 需要新采集 |
| A6 | 财务异常 | 失智老人反复买保健品、被诈骗 | 与候选 E 合流 |

**B. 沟通失真**

- B1 老人电话里永远说"都好"——**这是最普遍的一条，也是子女焦虑的根源**
- B2 复诊时无人能提供准确病史（← 第 11 节的三次对比表正好补这个）
- B3 兄弟姐妹间信息不同步 → 演变成"你都不管妈"的家庭冲突。**一份共享的客观记录能直接消解这类争吵**
- B4 换护工时，所有关于老人的隐性知识（他怕什么、几点犯困、哪只手不能扎针）全部丢失

**C. 失智特有**

- C1 **重复提问**——见下，这是最强的一条
- C2 走失
- C3 **忘了刚吃过又吃一次**——重复用药最危险的形态，且现有智能药盒完全防不住
- C4 妄想指控（见上）
- C5 **早期识别被延误 1–2 年**——家人当"老糊涂"，而早期干预对病程影响最大

**D. 子女侧的元痛点**

- D1 **决策焦虑**：要不要请护工？要不要送养老院？要不要辞职回老家？——现在全凭愧疚感做决定，没有任何数据
- D2 愧疚本身（这是最强的付费驱动力，且付费方是子女）

### D1 里藏着最好的一个功能：重复提问

失智老人一天问 30 遍"今天星期几""我女儿什么时候来"。护工和家人会不耐烦，会说"你都问十遍了"——而这句话对老人是实实在在的伤害。

**AI 可以第 30 遍还用完全一样的温和语气回答。这是极少数 AI 真正比人做得更好、而不只是更便宜的场景。**

但真正的价值在第二层：

> **这个交互本身就是一份被动采集的认知量表。**
> 提问频率、重复间隔、问题类型的迁移，构成一条纵向曲线——完全不需要任何人做测试。

传统 MMSE 量表要去医院、要预约、要老人配合，所以家庭几乎从不做，于是 C5（延误 1–2 年）就发生了。而"今天几号"这个问题老人每天自己会问几十遍。

**一个功能，同时解决 C1（陪伴）、C5（早期识别）、A4（有基线才能判断变化）、D1（决策有据）。** 这是整个头脑风暴里性价比最高的一条。

⚠️ **但医学边界必须守住**：这**不是诊断工具**。仍然遵守第 11 节那条铁律——只做**转录、对比、放大**。你只能说「本月平均每天重复提问 11 次，三个月前是 3 次」，**绝不能说**「这提示认知衰退」。前者是计数，后者是行医。产出物定位成"给医生的观察素材"和"给子女的变化提示"。

### 隐私红线：记录事件，不记录内容

这个方向最容易滑向监控，而监控会让产品死掉——老人拒绝、护工破坏、法律风险。

> **Log that something happened, not what was said in the room.**

- ✅ 记「08:03 确认服药」「昨夜 2:17 手机被拿起」「本周重复提问 47 次」
- ❌ 不做常开麦克风、不做摄像头、不做全屋录音

**双向知情 + 分层可屏蔽**：安全类事件（漏药、跌倒、症状主诉）不可屏蔽，且老人明确知情；生活类（今天心情不好、跟邻居拌嘴）老人有权说"这条别告诉我女儿"。

听起来违反直觉——你不是在给子女做监控吗？但**一个完全没有隐私的老人会拒绝使用这个产品**。给他一点控制权，是让他接受它的前提。

### 对路线图的影响

不改 14 天计划，但改**叙事**：

> 你收集的按钮点击流，**已经**是一份客观照护记录了。从「提醒工具」重新定位成「事实层」，边际成本接近零，价值和付费意愿高一个量级。

顺序建议：**① 吃药闭环（顺带产生记录）→ ② 化验单归档（医学事实）→ ③ 重复提问（认知曲线 + 陪伴）→ ④ 跌倒/夜间活动 → ⑤ 防诈骗**

第 11 天上门时，加问子女两个问题：
1. 「你怎么知道你妈今天吃药了？」
2. 「上次她摔跤，你是什么时候知道的、怎么知道的？」

**第二个问题的答案会告诉你这条路值不值得走。**

## 14. 变更记录：本文相对初稿改了什么

初稿写于讨论早期，以下修订均已合并进上文。列在这里是因为**其中几条推翻了初稿的判断**，
而推翻的理由本身比结论更有价值。

| # | 改动 | 为什么 |
|---|---|---|
| ① | **「只有一个按钮」→ 闹钟式三按钮** | 老人在外、药在家时，唯一出口是「吃了」——**设计本身在逼他撒谎**。给诚实出口比任何置信度算法都有效 |
| ② | **删掉"待机屏"，App 不常驻** | 手机是老人的，不是应用的。只在三个时刻出现：到点 / 有待办 / 主动打开。加了三条例外：**通话中不接管、不劫持返回键、不申请无关权限** |
| ③ | **补上拍照采集流程**（原来只有校对页） | 冷启动是第一道关。**不写使用说明，让 AI 看完再提具体要求**——"请翻到写着用法用量那一面"比"请拍摄完整包装"有效一个量级 |
| ④ | **实时取景 → 拍后反馈** | 微信 WebView 里 `getUserMedia` 不可靠、`wx.chooseImage` 需认证服务号。而服务端反馈**反而更具体**（能说"第 2 页挡住了 3 行"） |
| ⑤ | **补上联系人设置屏**，且**放在最后一步** | 手机号做第一屏 = 注册表单，转化会崩。放在拍完照之后，子女已投入 5 分钟 |
| ⑥ | **子女看板改三态** | 记录的是"按了按钮"不是"吃了药"。**虚假确定性比没有数据更危险** |
| ⑦ | **拨号按钮从 4 处收到 2 处**（仅 B3/C3） | 首页与它抢注意力。但 **B3 不可删**——否则"我联系不上她"之后没有出口 |
| ⑧ | **第二联系人：POC 不做** | 优先级/谁先响应/去重才是真复杂度。砍它省一整天，比砍拨号按钮划算得多 |
| ⑨ | **定名「吃药了 / ChiYaoLe」+ 黄底黑字图标** | 用汉字不用图形（认字不认图形）、用黄不用蓝（**白内障晶状体大量吸收蓝光**） |
| ⑩ | **主按钮 `#12A150` → `#0B6B33`** | 白字对比 3.4:1 → **7.4:1（AAA）**，语义不变，零成本 |
| ⑪ | **明确不做条形码 / 追溯码** | 条码只告诉你"是什么药"，不告诉你"这个人怎么吃"。v2 作为**校验器**（补 VLM 最易翻车的规格字段），不作主路径 |
| ⑫ | **检索用确定性 SQL，不用向量库；NL→固定意图不做 text-to-SQL** | 医疗数据里 **top-k 召回不全是静默失败**；生成的 SQL 会绕过归一化层 |
| ⑬ | **§13 战略重定位：从「助手」到「事实层」** | 按钮点击流**本身就是客观照护记录**，边际成本为零。且必须框成"**同时保护护工**"才落得了地 |
| ⑭ | **B 端首选社区卫生服务中心**（见文档 01 §7.3） | 他们管着 **1.15 亿**高血压患者、被考核控制率，而全国控制率只有 **16.8%**——**因为不知道人回家后有没有吃药** |
| ⑮ | **§6 合并为唯一权威排期** | 原来 §6 和 §11 各有一张日程表，是两个真相来源 |
| ⑰ | **装机加两道关，但刻意做小** | 只回答两个问题：**能不能装**（不能就直接说 + 给替代方案）、**要开哪些权限**（按机型给步骤）。<br>**不做严重程度分级、不做每日健康检查、不做上报看板**——那是监控系统，不是安装检测。<br>「装完被关掉」用现成信号覆盖：**闹钟不响 → 剂次没确认 → 子女已收到提醒**。<br>另：**华为纯净模式需华为账号才能退出**，是装机最可能卡死的一步 |
| ⑯ | **「打印贴冰箱」→「设成锁屏 / 发家庭群」** | **多数中国家庭没有打印机**，而这一步卡在冷启动——最不能有摩擦的位置。<br>但它原本承担三个作用，所以不是删而是换载体：<br>**零设备价值** → 锁屏（一天看几十次、零导航、永远在手边，**比冰箱更好**）<br>**故障兜底** → 锁屏 + 微信群图片（App 卸载了壁纸还在）<br>**冷启动诱饵** → 改由 **试听语音** 承担（情绪冲击强于一份打印稿，且零成本） |
